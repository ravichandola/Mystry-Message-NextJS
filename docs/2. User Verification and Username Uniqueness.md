# API Documentation: User Verification and Username Uniqueness

This document describes the API endpoints responsible for checking username uniqueness and verifying user registration codes.

## 1. `GET /api/check-username-unique`

This endpoint is used to check if a given username is already taken in the database.

### Purpose

To provide real-time feedback to users during registration, indicating whether their chosen username is available.

### Request

- **Method:** `GET`
- **URL:** `/api/check-username-unique`
- **Query Parameters:**
  - `username` (string, required): The username to check for uniqueness.

**Example Request:**

```
GET /api/check-username-unique?username=myuniqueusername
```

### Response

The response will be a JSON object indicating the success status and a message.

#### Success (HTTP 200 OK)

```json
{
  "success": true,
  "message": "Username is available"
}
```

#### Error (HTTP 400 Bad Request)

- **Invalid Query Parameters:** If the `username` query parameter is missing or does not conform to the `usernameValidation` schema.

  ```json
  {
    "success": false,
    "message": "Invalid query parameters",
    "errors": ["Username must be at least 3 characters long"]
  }
  ```

- **Username Already Taken:** If the username is found in the database and is already verified.

  ```json
  {
    "success": false,
    "message": "Username is already taken"
  }
  ```

#### Error (HTTP 500 Internal Server Error)

- **Server-Side Error:** If an unexpected error occurs during the username check process.

  ```json
  {
    "success": false,
    "message": "Username check error"
  }
  ```

### Logic

1.  **Database Connection:** Establishes a connection to the MongoDB database.
2.  **Query Parameter Extraction:** Extracts the `username` from the request's URL query parameters.
3.  **Validation:** Validates the extracted `username` against the `usernameValidation` Zod schema. Returns a 400 error if validation fails.
4.  **Database Lookup:** Queries the `userModel` to find a user with the provided `username` and `isVerified: true`.
5.  **Response:**
    - If a matching user is found, returns a 400 status with "Username is already taken".
    - If no matching user is found, returns a 200 status with "Username is available".
6.  **Error Handling:** Catches any unexpected errors during the process and returns a 500 status.

## 2. `POST /api/verify-code`

This endpoint is used to verify a user's registration code.

### Purpose

To finalize the user registration process by validating the verification code sent to the user's email/phone.

### Request

- **Method:** `POST`
- **URL:** `/api/verify-code`
- **Request Body (JSON):**
  - `username` (string, required): The username of the user to verify.
  - `code` (string, required): The verification code provided by the user.

**Example Request Body:**

```json
{
  "username": "testuser",
  "code": "123456"
}
```

### Response

The response will be a JSON object indicating the success status and a message.

#### Success (HTTP 200 OK)

```json
{
  "success": true,
  "message": "Email verified successfully"
}
```

#### Error (HTTP 404 Not Found)

- **User Not Found:** If no user with the provided username is found in the database.

  ```json
  {
    "success": false,
    "message": "User not found"
  }
  ```

#### Error (HTTP 400 Bad Request)

- **Invalid Verification Code:** If the provided `code` does not match the `verifyCode` stored for the user.

  ```json
  {
    "success": false,
    "message": "Invalid verification code"
  }
  ```

- **Expired Verification Code:** If the `verifyCodeExpiry` for the user has passed.

  ```json
  {
    "success": false,
    "message": "Verification code has expired, please signup again to get a new code"
  }
  ```

#### Error (HTTP 500 Internal Server Error)

- **Server-Side Error:** If an unexpected error occurs during the verification process.

  ```json
  {
    "success": false,
    "message": "Verify code error"
  }
  ```

### Logic

1.  **Database Connection:** Establishes a connection to the MongoDB database.
2.  **Request Body Extraction:** Parses the JSON request body to extract `username` and `code`. The `username` is then URL-decoded.
3.  **User Lookup:** Finds the user in the `userModel` using the decoded `username`.
    - If no user is found, returns a 404 error.
4.  **Code and Expiry Validation:**
    - Compares the provided `code` with the `user.verifyCode`.
    - Checks if the current date is before `user.verifyCodeExpiry`.
5.  **Verification Status Update:**
    - If both `isCodeValid` and `isCodeNotExpired` are true, sets `user.isVerified` to `true` and saves the user document. Returns a 200 success.
    - If `isCodeValid` is false, returns a 400 error for an invalid code.
    - If `isCodeNotExpired` is false, returns a 400 error for an expired code.
6.  **Error Handling:** Catches any unexpected errors during the process and returns a 500 status.
